# 决策链路由算法

> 实现位置：
> - 决策链：`backend/app/routing/decision.py`（`route()` / `_resolve_pin()` / `_score()`）
> - 能力解析：`backend/app/routing/capabilities.py`（`detect_capabilities()` / `estimate_prompt_tokens()`）
> - 入口：`backend/app/routers/openai.py`（`/v1/chat/completions`、`/v1/embeddings`）
> - 账本/启停：`backend/app/ledger/book.py`（`compute_cost()` / `record_usage()` / `sync_model_states()`）

---

## 0. 总览：一次请求如何走到选中的模型

```
请求进入 openai.py
  ├─ /v1/chat/completions  → route(kind="chat")
  │     required = detect_capabilities(messages, response_format, tools)
  └─ /v1/embeddings        → route(kind="embedding")
        required = {"embedding"}   # 不看消息

route() 内部：
  1. 解析所需能力集 required（仅 chat 走 detect_capabilities）
  2. _resolve_pin()：客户端指定的 model 是否继续生效（不生效→降级为「未传」）
  3. 遍历全量 Model，逐层硬过滤 → 候选集 C（带 reasons）
  4. pin 仍生效 且 C 为空  → 能力不匹配 400（强一致早失败）
  5. C 为空            → escape 兜底 / embedding 缺口 400 / 结构化缺口 400 / 503
  6. _score(C, strategy) 排序取第一名
         ↓
  RouteResult(model, package, est_cost, candidates, reasons,
              strategy, escaped, pin_requested, pin_dropped)
         ↓
  openai.py 调执行器 complete()/embed()，回写 data["model"]，record_usage 扣账
```

`RouteResult` 关键字段：
- `model` / `package`：选中的模型与额度包
- `est_cost` / `candidates`：估算成本、按策略排序后的候选 id 列表（第一名即选中）
- `reasons`：每个被过滤模型的原因（排查用）
- `strategy`：实际采用的策略
- `escaped`：是否走到 escape 兜底
- `pin_requested` / `pin_dropped`：客户端原指定名、降级原因（`None` 表示未降级）

---

## 1. 所需能力解析（chat）

`detect_capabilities(messages, response_format, tools)` 返回 `set[str]`：

| 触发条件 | 追加能力 |
|---|---|
| 默认 | `chat` |
| 某 message 含图片（多模态 / `image_url`）或文本含视觉词（图/image/画/描述这张/识别/ocr/截图） | `vision` |
| 文本含代码标记（`def`/`function`/`import`/`class`/```/代码/编程/算法/sql/select） | `code` |
| 文本长度 > 4000 字符 | `long_context` |
| 文本含 tool/function_call/调用/工具，或请求带 `tools` | `function_calling` |
| `response_format.type == "json_schema"` | `json_schema` |
| `response_format.type == "json_object"` | `json_object` |
| 请求携带 `tools` | `function_calling` |

> 文本判定为**关键词启发式**，非语义理解；结构化输出能力只看 `response_format` / `tools` 参数，与消息文本无关。
> `embedding` 不走此函数，`required` 恒为 `{"embedding"}`，且 `est_prompt = est_completion = 0`。

## 2. 指定模型（pinned）的解析与降级  ← 关键规则

客户端可在请求体传 `model`（OpenAI 兼容字段），语义如下：

- **不传 / 空串 `""`** → `pinned = None` → 纯自动选择。
- **传具体值** → 按 `Model.id` **或** `Model.provider_model` 匹配（二者等价）：
  - 推荐用 `id`（如 `qwen-max`、`deepseek-self`）；
  - 也可用 `provider_model` 串（如 `deepseek-chat`、`qwen-max`）。

### `_resolve_pin(session, pinned)`

判定该名字是否继续生效，返回 `(生效的 pinned, 丢弃原因)`：

| 情况 | 返回 | 后果 |
|---|---|---|
| 池中完全不存在该名称（id 与 provider_model 都不匹配） | `(None, "not_found")` | 降级为自动选择 |
| 存在，但**所有同名匹配模型都不「基础可用」** | `(None, "unavailable")` | 降级为自动选择 |
| 至少有一个同名匹配模型「基础可用」 | `(pinned, None)` | 继续锁定该名字 |

**基础可用**（`_model_basically_usable`）= 平台启用 **且** 模型启用 **且** 未手动禁用 **且** 未过期 **且** 额度充足。
即「被停用 / 平台禁用 / 已过期 / 额度耗尽」统一判为 `unavailable` 并**降级**，请求进入自动选择，不再因该模型报 400。

> 同名可能跨平台命中多个模型（见 §2 末边界）。`_resolve_pin` 只看基础可用性；能力在 §3 主循环校验。

### 唯一保留 400 的情形（强一致早失败）

pin 名字**存在且基础可用**，但**能力不满足**请求所需（如指定仅 `json_object` 的模型却要 `json_schema`）：
主循环过滤后候选为空，且 `pin_effective` 仍非空 → 返回 **400**，提示改用支持该能力的模型。
这样避免把强一致请求悄悄转给不相干模型，行为不可预期。

### 边界（已知）

`escape` 种子的 `provider_model` 恰好也是 `qwen-max`。因此指定 `qwen-max`（provider_model 串）会同时命中 `qwen-max` 与 `escape`；若请求仅需 `chat`，按策略打分后理论上可能选到 `escape`。如希望指定 `id` 不被 escape 干扰，可把 escape 排除出 pin 匹配（当前未做，待定）。

## 3. 硬过滤（逐层 AND → 候选集 C）

遍历 `Model` 全表，命中即 `continue` 并记录原因到 `reasons[m.id]`：

1. **平台启用**：`platform.enabled` 否则 `platform_disabled`
2. **模型启用**：`model.enabled` 且 非 `manual_disabled` 否则 `model_disabled`
3. **未过期**：`not model.is_expired` 否则 `expired`
4. **能力匹配**：`required ⊆ model.capabilities`，缺则 `cap_missing:[缺失项]`
5. **额度充足**：额度来源非 `none` 且 `quota_balance_eff > 0`，否则 `quota_exhausted`
6. **pin 锁名**：`pin_effective` 非空 且 `id != pin_effective` 且 `provider_model != pin_effective` → `not_pinned`

全部通过者，估算 `est_cost = book.compute_cost(m, est_prompt, est_completion)` 加入候选：

- `est_prompt` = `estimate_prompt_tokens(messages)`（中文≈3 字符/token 粗估）
- `est_completion` = chat `512`（`OUT_TOKENS_EST`）/ embedding `0`
- `compute_cost`：按 `effective_billing_type` 分叉——`call` 计费取 `price_per_call`；`token` 计费 = `prompt/1000×price_input + completion/1000×price_output`

> 路由**不依赖** `enabled` 单一来源：即使 `sync_model_states` 未跑或落库滞后，过期/额度耗尽仍会被步骤 3、5 硬过滤掉（双保险）。

---

## 4. 打分与路由策略

`strategy = 请求体 route_strategy 或 环境变量 LLM_POOL_ROUTE_STRATEGY（默认 balanced）`

| 策略 | 排序键（高者优先） | 说明 |
|---|---|---|
| `lowest_cost` | `est_cost` 升序 | 最便宜 |
| `highest_quality` | `quality_tier` 降序，同档按剩余额度 | 质量优先 |
| `lowest_latency` | `latency_tier` 升序（越低越快），同档按 `quality_tier` 降序 | 速度优先 |
| `expiring_soon` | `expired_at` 升序（未设→`+∞` 排最后），同档按剩余额度 | 临期优先消耗 |
| `balanced`（默认） | `score` 降序，同分按剩余额度 | 质量/成本权衡 |

- `balanced`：`score = QUALITY_WEIGHT·norm_q − (1−QUALITY_WEIGHT)·norm_cost`
  - `norm_q = quality_tier / max_q`，`norm_cost = est_cost / max_cost`
  - `QUALITY_WEIGHT` 默认 `0.6`（环境变量 `LLM_POOL_QUALITY_WEIGHT`）
- **剩余额度** `_balance(m)`：共享包取 `package.balance`；独立额度取 `quota_balance_eff`；无额度（none）取 `+∞`（平分时永远排最前）。

> 前端控制台当前未暴露 `route_strategy` 选择器，需直接调 API 传该字段临时覆盖全局默认。

---

## 5. 候选为空 / 兜底

C 为空时按以下顺序处理：

1. **pin 能力不匹配**（§2）→ `400`：提示指定模型不满足所需能力，请改用支持该能力的模型或不传 model。
2. **escape 兜底**（`LLM_POOL_ESCAPE_MODEL_ID`，默认 `escape`）：若已配置且 `enabled`、未手动禁用、额度充足、且 `required ⊆ escape.capabilities` → 直接选它（`escaped=True`），不再看成本/余额。
3. **embedding 无候选** → `400`：提示为支持 embeddings 的模型打 `embedding` 能力标签。
4. **结构化输出缺口** → `400`：`required` 含 `json_schema/json_object/function_calling` 但无可用模型支持，提示打对应标签或改用支持 `json_schema` 的模型。
5. 其余（纯 chat 无候选且未触发 escape）→ `503`：`无可用模型（候选为空）`。

> escape 仅声明 `chat` 能力，故只兜底纯对话请求；embedding / 结构化请求不会落到 escape，会走对应的 400。

---

## 6. 执行与回写

选中 `M` 后由 `openai.py` 调执行器：

- chat：`complete(M, M.platform, messages, stream=req.stream, **extra)`
- embedding：`embed(M, M.platform, req.input, **extra)`

`extra` = 请求 `model_extra`（OpenAI 透传字段）+ 显式字段：
- chat：`temperature` / `max_tokens` / `response_format` / `tools` 等
- embedding：`encoding_format` / `dimensions` 等

执行后回写 `data["model"] = M.id`，并 `book.record_usage(...)` 扣减账本；embedding 的 `completion_tokens = 0`（仅按输入 token 计费）。

## 7. 可观测性

- **路由日志** `[ROUTE]`（每次调用必打）：
  `pinned / pin_dropped / model_id / platform / provider / provider_model / escaped / strategy / candidates`
  降级时额外 `logger.warning("pinned=... 不可用（...），按未传处理")`。
- **降级响应头**（仅 pin 被丢弃时出现，对话非流式/流式与 embeddings 均回写）：
  - `X-LLM-Pool-Pin-Requested`：客户端原指定的名字
  - `X-LLM-Pool-Pin-Dropped`：`not_found` / `unavailable`
- **过滤原因**：`RouteResult.reasons` 记录每个候选被淘汰的原因，供排查与策略调优。

---

## 8. 模型自动启停（与路由的协作）

`ledger/book.py::sync_model_states` 重算 `enabled`：

- **置否（false）**：`manual_disabled` > `is_expired` > 额度耗尽（`quota_balance_eff <= 0`）
- **置真（true）**：未过期、额度未耗尽、且非手动关闭
- 额度来源分叉：
  - 共享包耗尽 → **级联禁用**该包下全部模型
  - 模型独立额度耗尽 → 仅禁用自身
  - 无额度（none）→ 不扣减、不自动禁用
- **恢复**：额度补充（`used` 回落）后，经 `POST /admin/sync` 或定时任务重新置 `true`；手动关优先级最高，不被自动逻辑覆盖。

> 路由与启停是**双保险**：路由硬过滤（§3）独立生效，不依赖 `sync` 是否运行或落库是否及时。

## 9. 配置项汇总

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_POOL_ROUTE_STRATEGY` | `balanced` | 全局默认路由策略 |
| `LLM_POOL_QUALITY_WEIGHT` | `0.6` | `balanced` 下质量权重（成本权重 = `1 − 该值`） |
| `LLM_POOL_ESCAPE_MODEL_ID` | `escape` | 兜底模型 id（空字符串=不兜底） |

请求级覆盖：在 `/v1/chat/completions`、`/v1/embeddings` 请求体传 `route_strategy` 字段，临时覆盖全局默认（不影响其他请求）。
