# 决策链路由算法

## 0. 前提

- 平台 `enabled == false` → 旗下模型全剔除（平台级硬开关）。
- 模型 `enabled == false` → 直接剔除（模型级硬开关；过期 / 额度耗尽触发自动置否，亦可手动关，锁定决策③修订）。
- 若请求显式指定 `model`（pinned）→ 仅校验该模型是否通过下列过滤，通过则直发，否则返回 400。

## 1. 请求解析 → 所需能力集（确定性，从请求结构抽取）

- 任意 message 含图片 → needs `vision`
- 含 `tools` / `function_call` → needs `tool_use`
- 估算总 token > 长上下文门槛 → needs `long_context`
- 默认 needs `chat`
- （可选）复杂度分类决定是否需要 `reasoning`（启发式或 RouteLLM 插件，后续扩展）

## 2. 硬过滤（逐层 AND，得到候选集 C）

0. **模型启用**：`model.enabled == true`（手动关 或 过期 / 额度耗尽自动关）
1. **平台启用**：`platform.enabled == true`
2. **能力匹配**：`model.capabilities ⊇ required_capabilities`
3. **未到期**：`model.expired_at` 为空 或 > now
4. **余额充足**：额度来源非 none 且 `quota_balance_eff > 0`（`quota_balance_eff` 对共享包取 `package.balance`，对独立额度取 `model.quota_capacity - model.quota_used`，对 none 返回 None 表示不限量）。

## 3. 成本 / 质量打分（C 内排序）

对每个候选估算成本：
- 按Token：`est_cost = est_tokens/1000 × input_price + est_tokens/1000 × output_price`（est_tokens 由消息粗估）
- 按次：`est_cost = price_per_call`（固定）

策略（可配置，默认 `balanced`）：
- `lowest_cost`：选 est_cost 最小者
- `highest_quality`：选 quality_tier 最高者（同档按剩余额度优先）
- `lowest_latency`：选 latency_tier 最低（最快）者
- `expiring_soon`：快到期优先——按 `expired_at` 升序，临近过期的模型先被选中；无到期时间的模型排最后（同到期时间者按剩余额度优先）
- `balanced`：`score = w_q·norm(quality) − w_c·norm(cost)`，取最大

> 注：早期设计稿曾规划带门槛/预算的 `min_cost_above_quality_bar`、`best_quality_under_budget`，实现时简化为 `highest_quality` / `lowest_latency`，避免引入额外运行时参数。`expiring_soon` 为后续新增策略，置于 `balanced` 之前。

平局：按历史延迟 / 随机。

## 4. 降级与兜底

- C 为空（全部禁用 / 过期 / 耗尽 / 不匹配能力）→ 返回 503 + 原因（如 `no_capable_model` / `all_exhausted`）。
- 可选 escape 模型：用户开启后，在 C 为空时退化为"仅满足能力与未到期、忽略成本/余额"的模型（须显式配置，避免隐性超支）。

## 5. 执行与回写

- 选中模型 M，取 `platform.base_url / api_key` 与 `provider_model_id`。
- 调 `litellm.completion(model=M.provider_model_id, api_base=platform.base_url, api_key=platform.api_key, messages=..., stream=..., **kwargs)`。
- 流式回传 OpenAI 格式；流结束读 usage → 按设计03 扣减账本。

## 6. 可观测

- 每次路由记录：选中模型、估算成本、实际成本、被过滤掉的原因分布，供调优策略权重。

## 7. 模型自动启停

- **自动置否（enabled=false）触发条件**：`now > expired_at`，或 额度来源非 none 且 `quota_balance_eff <= 0`（共享包耗尽 / 独立额度耗尽）。独立额度耗尽仅停用自身，共享包耗尽级联停用其下全部模型。
- **触发来源**：定时维护任务 或 请求时惰性检查（双保险）。即便自动置否尚未落库，第 2 节的过期 / 余额硬过滤仍独立生效，不会误路由。
- **恢复**：过期为永久关闭；额度耗尽置否后，包补充（used 回落）可经手动 或 定时任务重新置 true。手动关闭优先级最高，不会被自动逻辑覆盖。
