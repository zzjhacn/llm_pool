# 总体架构与统一接口设计（方案A：LiteLLM 当执行器，自建大脑）

> 本文档为设计稿，**不进入开发**。目的是锁定分层边界与对外接口形态。

## 1. 分层定位

| 层 | 负责方 | 职责 |
|---|---|---|
| **大脑（自建）** | 我们的服务 | 平台/模型/额度包注册表、Token 池账本、决策链路由、统一 OpenAI 接口、计费与统计 |
| **执行器（LiteLLM）** | 纯协议适配 | 把统一请求翻译成各厂商协议、SSE 流式、重试与错误码映射。**不**承担路由、预算、Key 管理 |

关键原则：**路由、预算、额度、Key 管理 100% 在我们侧**；LiteLLM 只用其 provider 适配能力，调用时显式传 `api_base` / `api_key` / `model`，绕开其自带 router。因此我们自定义字段（enabled、expired_at、billing_type、共享额度）LiteLLM 完全无感，互不冲突。

## 2. 请求流向

```
客户端
  │  POST /v1/chat/completions (OpenAI 风格)
  ▼
统一网关 (FastAPI)
  │  决策链：挑模型 + 选额度包
  ▼
litellm.completion(model, api_base, api_key, messages, stream)
  │
  ▼
厂商 API
  │  SSE 流式回传
  ▼
网关透传 OpenAI 格式给客户端
  │  流结束读取 usage
  ▼
账本扣减（Token 池账本）
```

## 3. 统一接口（OpenAI 风格）

业务面（对外暴露，网关 key 鉴权）：
- `POST /v1/chat/completions` —— 主路由，支持 `stream`
- `POST /v1/embeddings` / `POST /v1/completions` —— 可选扩展
- `GET  /v1/models` —— 列出当前可用模型，可带 `capability` 过滤

管理面（建议 `/admin` 前缀，独立鉴权）：
- `CRUD /admin/platforms` —— 维护平台地址、key、是否可用
- `CRUD /admin/models` —— 维护模型名、能力、价格、到期、启用开关、所属包
- `CRUD /admin/packages` —— 维护额度包（总资源量、已用）
- `GET  /admin/ledger` —— 余额、累计成本、各模型命中统计

鉴权说明：客户端用**网关 key** 调统一接口；网关内部按决策链选中模型后，用**平台 key** 调厂商，平台 key 不对外暴露。

## 4. 技术栈（建议，非锁定）

### 4.1 业务侧（后端）
- Python 3.12 + FastAPI（统一接口）
- LiteLLM（库调用 `litellm.completion`，非 proxy 模式）
- SQLite + SQLAlchemy（注册表与账本；账本需事务原子扣减，v1 用 SQLite，后续可换 Postgres）
- 初始种子可用 YAML/JSON 导入，运行时变更落库

### 4.2 页面侧（管理控制台）
- **Vue 3 + Vite**（构建/SPA 框架）
- **Element Plus**（平台/模型/额度包 CRUD 的表单、表格、对话框等现成组件）
- **ECharts**（账本看板：余额趋势、累计成本、各模型命中占比）
- **Pinia**（前端状态，含登录态/网关 token）+ **Axios**（HTTP 客户端）
- **鉴权**：管理面独立登录，登录后拿管理 token（与网关 key 分离），Axios 拦截器自动带 `Authorization`。

### 4.3 前后端衔接约定
- 页面侧只消费已定义的 `/admin/*` REST 接口与 `GET /admin/ledger`；接口契约见第 3 节，前后端解耦。
- 部署形态（v1 二选一，倾向后者）：
  1. 独立静态站点（Vite build 产物）经 CORS 调 FastAPI；
  2. FastAPI 用 `StaticFiles` 挂载 `dist/`，同源访问、免 CORS 配置。【推荐】
- 业务面（`/v1/*`）客户端不依赖此页面，页面仅服务运维人员。

## 5. 与 LiteLLM 的边界（重申）

- 路由、预算、额度、Key 管理：我们侧。
- 厂商协议适配、SSE、重试、错误映射：LiteLLM 侧。
- 我们自定义字段 LiteLLM 无感，不会与之冲突（无 merge 成本）。
